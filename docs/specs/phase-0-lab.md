# Phase 0: Lab

Status: proposal (needs-triage). Blocked by: none.

## Problem Statement

Every rule needs Tier 0 evidence from the pinned Rails, and every eval needs a clean application to run against. Without a committed lab, "what Rails generates" is remembered rather than observed, and the memory is years out of date.

## Solution

Two Rails 8.1.4 applications on Ruby 3.4.x, generated by `rails new` with defaults, one on Minitest and one on RSpec, with scaffold, authentication, a Turbo Stream broadcast and a Solid Queue job generated and committed untouched. A setup script regenerates them anywhere.

## User Stories

1. As the doctrine author, I want the exact generator output for 8.1.4 committed, so that a rule can cite a file instead of a memory.
2. As the eval harness, I want a green, boot-able app per testing convention, so that every eval task starts from the same state.
3. As the owner, I want to diff generator output across Rails bumps, so that I see what the core team changed in their defaults.
4. As a skill author, I want examples lifted from generated code, so that examples are never hand-written.

## Implementation Decisions

- Location `lab/minitest_app` and `lab/rspec_app`; a `lab/SOURCES.md` records installed gem paths and the exact Ruby and Rails versions used.
- Ruby via rbenv in the cloud container (3.4.12 if installable, otherwise newest 3.4.x offered; record which). Docker is unavailable there.
- Generators run in this order and each is its own commit: `rails new`, `scaffold Post title body:text`, `authentication`, `model Comment post:references body:text`, a `Comment` Turbo Stream broadcast, a `PostSummaryJob` on Solid Queue. The RSpec app adds `rspec-rails` and runs `rspec:install` before scaffolding so generated specs appear.
- Generated files are never edited in the lab; doctrine examples that need changes live under `examples/`, outside the lab.
- A `bin/setup-lab` script performs the whole sequence and fails loudly if any step would alter a previous commit.

## Testing Decisions

- Done when `bin/ci` is green in both apps and `git diff` between generation steps is recorded under `lab/diffs/`.
- No hand-written tests in this phase; the generated tests are the tests.

## Out of Scope

- Any rule, hook or skill content.
- PostgreSQL variants of the lab (a later ticket if a project needs it).

## Checklist

- [ ] RubyGems and GitHub reachable from the cloud container through the proxy; record the result in `lab/SOURCES.md`.
- [ ] Ruby 3.4.x installed with rbenv; `.ruby-version` committed.
- [ ] `rails new minitest_app` on 8.1.4 with defaults, committed untouched.
- [ ] `rails new rspec_app --skip-test`, rspec-rails added, `rspec:install` run, committed untouched.
- [ ] Scaffold, authentication, Comment model, broadcast and job generated in both apps, one commit per generator.
- [ ] `bin/ci` green in both apps.
- [ ] `lab/diffs/` holds one diff per generator step.
- [ ] `lab/SOURCES.md` lists `bundle show` paths for rails, activerecord, actionpack, activesupport, railties, turbo-rails, stimulus-rails, importmap-rails, propshaft, solid_queue.
- [ ] `bin/setup-lab` regenerates both apps from scratch and ends green.
